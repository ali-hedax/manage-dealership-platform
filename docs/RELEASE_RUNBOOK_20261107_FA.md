# راهنمای انتشار شنبه — نسخهٔ یکپارچهٔ main

این راهنما برای انتشار نسخهٔ یکپارچهٔ `main` روی سرور Manage است. مالک در 2026-11-05 دستور یکپارچه‌سازی و انتشار نسخهٔ نهایی را داد. انتشار از رایانهٔ مالک انجام می‌شود، چون کلید SSH سرور Manage و پشتیبان‌های رمزشده آن‌جاست. Source by HEDAX و سرور آن دست نمی‌خورد.

## چه چیزی روی سرور عوض می‌شود

- سرور الان `79f6585` را اجرا می‌کند (ارسال کارشناسی و روزکاری، [گزارش انتشار](RELEASE_DISPATCH_DAYS_20261105.md)).
- تنها تغییر کد: **بازیابی دسترسی کارکنان** (PR #47): مالک برای همکاری که رمز یا Authenticator را گم کرده، لینک یک‌ساعته و یک‌بارمصرف می‌سازد.
- **بدون migration، بدون seed، بدون تغییر `.env`.** تعداد migrationها همان ۱۶ (`0000` تا `0015`) می‌ماند.
- **اگر فاز ۱ (`feature/phase1-roles`) و ظاهر تازه (`feature/new-look`) پیش از شنبه در main ادغام شوند:** migration افزایشی `0016` اضافه می‌شود (ستون‌های `users.pin_hash`، `sessions.auth_method`، `tenants.settings` و جدول `case_alert_responses`). پس مرحلهٔ ۳ باید تمرین migration روی نسخهٔ بازیابی‌شده و مقایسهٔ اثرانگشت همهٔ ردیف‌های قبلی را هم داشته باشد، مثل انتشار `0015`.

- اگر فاز ۲ در نسخهٔ هدف ادغام شده باشد، migration افزایشی `0017_parts_workbench` را روی نسخهٔ بازیابی‌شده تمرین کنید و حفظ ردیف‌های قبلی را بررسی کنید.

## نسخهٔ هدف

آخرین commit شاخهٔ `main` که هر شش بررسی CI آن سبز است. تصاویر همان commit در artifact با نام `preview-images-<commit کامل>` از همان اجرای CI دریافت می‌شود؛ هیچ تصویری روی سرور ساخته نمی‌شود.

## مراحل (همان روال انتشارهای قبلی)

1. **پیش از شروع:** وضعیت سالم سرور، فضای دیسک و نبود تغییر ثبت‌نشده در checkout سرور. `deploy.sh` اجرا نشود (reset --hard دارد؛ [DEPLOYMENT](DEPLOYMENT.md)).
2. **دریافت artifact:** SHA256 فایل ZIP با digest گیتهاب و فایل `preview-images.sha256` داخل آن مقایسه شود؛ `preview-image-source.txt` باید همان commit هدف باشد.
3. **پشتیبان پیش از نصب:** `pg_dump -Fc` با برچسب `operational/<زمان UTC>`، بازیابی در پایگاه جدا و مقایسهٔ اثرانگشت جداول و migrationها ([BACKUP_RESTORE](BACKUP_RESTORE.md)).
4. **نصب:** `docker load` تصاویر، نگه‌داشتن تصاویر فعلی با برچسب rollback، تعویض API و web با هر سه فایل Compose. وقفهٔ مورد انتظار کمتر از یک دقیقه.
5. **بررسی زنده:** سلامت PostgreSQL، صفحهٔ ورود و manifest عمومی، پاسخ 401 برای API بدون نشست، و در نشست مالک فقط مشاهدهٔ بخش «کارکنان» و دکمهٔ ساخت لینک بازیابی (بدون ساختن لینک واقعی).
6. **پشتیبان نهایی:** بازیابی در پایگاه جدا، تطبیق اثرانگشت‌ها، حذف پایگاه‌های موقت، نسخهٔ رمزشدهٔ DPAPI در `Documents/Manage Backups`.
7. **ثبت:** گزارش انتشار `docs/RELEASE_INTEGRATION_<تاریخ>.md`، به‌روزرسانی PROGRESS، TEST_REPORT، DEPLOYMENT و BACKUP_RESTORE در یک PR مستندات.

## بازگشت

اگر هر بررسی شکست خورد: تصاویر rollback برگردانده شوند. چون migration ندارد، پایگاه داده نیازی به بازگردانی ندارد مگر داده‌ای خراب شده باشد؛ در آن صورت از پشتیبان پیش از نصب.

## پس از انتشار

شروع فاز ۱ طرح نقش‌محور: خاموش کردن گیت مالی و جایگزینی با هشدار پیش‌پرداخت و مبلغ (آستانهٔ اولیه ۵۰۰٬۰۰۰٬۰۰۰ ریال)، آزادی قیمت قطعه، خبر رسیدن قطعه روی کارت تعمیرکار، و ورود تعمیرکار با نام کاربری و رمز ۴ رقمی.
