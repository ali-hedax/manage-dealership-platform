# کارکنان و دعوت ایمیلی

این قابلیت از PR #24 روی Preview نصب است. بررسی اتصال و نمایش علت شکست از شاخه `fix/invitation-email-delivery` اضافه می‌شود. تا باز شدن مسیر اینترنت بین‌الملل سرور، ارسال ایمیل از Preview ممکن نیست و لینک دعوت خصوصی مسیر فعال است (بخش «عیب‌یابی» را ببینید).

## کار مالک

1. از منوی پنل، «کارکنان» را باز کنید. این بخش فقط برای نقش دارای مجوز `user.manage`، یعنی «مدیر سیستم»، نمایش داده می‌شود. حساب مالک اولیه هم نقش مدیر سیستم و هم مدیر خدمات را دارد.
2. نام، ایمیل و نقش‌های موردنیاز همکار را وارد کنید. مدیر سیستم اجازه مدیریت کارکنان می‌دهد؛ آن را فقط به مسئول موردنظر بدهید.
3. «افزودن و ارسال دعوت» را بزنید. نتیجه ارسال در همین صفحه نشان داده می‌شود؛ صرف ساخته‌شدن حساب، موفقیت ارسال ایمیل نیست.
4. همکار ایمیل را باز می‌کند، رمز شخصی با حداقل ۱۲ نویسه می‌سازد، QR مخصوص Manage را در Google Authenticator متصل و اولین کد را تأیید می‌کند.
5. برای ورود بعدی، همکار از نشانی عمومی `/login` با ایمیل، رمز و کد تازه Authenticator خودش وارد می‌شود. کد تأیید حساب Google یا ورودی Authenticator یک سامانه دیگر جای آن را نمی‌گیرد.

## وضعیت‌ها

فهرست کارکنان وضعیت «فعال»، «دعوت ارسال‌شده»، «ارسال ناموفق»، «دعوت منقضی» یا «نتیجه ارسال نامشخص» را نشان می‌دهد. «ارسال‌شده» یعنی سرویس ایمیل پیام را پذیرفته است؛ رسیدن به Inbox تضمین نمی‌شود و همکار باید Spam را هم بررسی کند.

دعوت ۲۴ ساعت اعتبار دارد. برای حساب فعال‌نشده، «ارسال دوباره دعوت» لینک تازه می‌فرستد و لینک/اتصال ناتمام قبلی را باطل می‌کند؛ حساب تکراری نمی‌سازد. حساب فعال دوباره دعوت یا بازنویسی نمی‌شود. تغییر رمز، بازیابی عامل دوم، کد پشتیبان و غیرفعال‌کردن حساب هنوز جزء این قابلیت نیستند.

اگر ارسال شکست بخورد، حساب در حالت انتظار باقی می‌ماند و خطا صریح نمایش داده می‌شود. پس از رفع تنظیم فرستنده، مالک دوباره ارسال می‌کند. ارسال خودکار مجدد یا صف ایمیل پس‌زمینه وجود ندارد؛ اگر اجرای برنامه وسط ارسال قطع شود، نتیجه نامشخص می‌ماند و موفقیت ادعا نمی‌شود. فقط تازه‌ترین دعوت معتبر است.

## فرستنده و حریم خصوصی

فرستنده در تنظیمات خصوصی سرور با `SMTP_HOST`، `SMTP_PORT`، `SMTP_SECURE`، `SMTP_USER`، `SMTP_PASSWORD` و `SMTP_FROM` تنظیم می‌شود. پیش‌فرض نمونه Gmail روی ۴۶۵/TLS است. در حالت STARTTLS، ارتقای TLS الزامی است؛ اعتبار گواهی غیرفعال نمی‌شود. برای Gmail از App Password استفاده کنید؛ رمز اصلی Gmail یا کد شش‌رقمی Authenticator، رمز SMTP نیست. ساخت/مدیریت رمز برنامه با خود مالک در Google انجام می‌شود.

بدون تنظیم کامل فرستنده، دکمه ارسال غیرفعال است و API پیش از ایجاد حساب خطای روشن می‌دهد. اگر فرستنده تنظیم شده ولی Google آن را نپذیرد، شکست ارسال ثبت می‌شود. هیچ رمز SMTP، لینک دعوت، QR یا خطای خام سرویس ایمیل در گزارش عمومی، audit، Git یا پاسخ مسیر ارسال ایمیلی ذخیره/بازگردانده نمی‌شود. فقط هش دعوت در DB نگهداری می‌شود؛ متن لینک برای فرستادن همان پیام موقتاً در حافظه است.

برای شروع سریع، حتی پیش از آماده‌شدن ایمیل، می‌توانید پس از واردکردن مشخصات «ساخت لینک دعوت خصوصی» را بزنید و لینک را فقط برای همان همکار بفرستید. در این حالت صریحاً نوشته می‌شود ایمیلی ارسال نشده است. ورود، رمز و Authenticator همکار دقیقاً همان مسیر امن هستند. اگر ارسال ایمیل شکست خورده باشد، از فهرست هم امکان ساخت لینک خصوصی تازه هست. لینک با تازه‌سازی صفحه از UI پاک می‌شود و در مرورگر ذخیره نمی‌شود. مسیر bootstrap خصوصی هم حفظ شده است. محدودیت API ارسال: پنج درخواست در دقیقه برای هر IP. [جزئیات API](API.md) و [ورود شخصی](PERSONAL_AUTH_FA.md).

## عیب‌یابی ارسال ایمیل

- **بررسی اتصال ایمیل** (بالای صفحه کارکنان): از همان سرور Manage به سرور ایمیل وصل می‌شود، TLS را برقرار و فرستنده را احراز می‌کند و **هیچ پیامی نمی‌فرستد**. نتیجه با یکی از دسته‌های زیر نمایش و در سابقه ثبت می‌شود.
- اگر ارسال دعوت شکست بخورد، علت در همان پیام و زیر نام همکار در فهرست نمایش داده می‌شود. پس از ارسال موفق، علت پاک می‌شود.

| دسته | معنا | اقدام |
| --- | --- | --- |
| تنظیم نشده | فرستنده روی سرور تنظیم نشده | تنظیم خصوصی با `configure-smtp.sh` |
| اتصال برقرار نشد (`connection_blocked`) | سرور Manage به سرور ایمیل نمی‌رسد (مسدود یا بدون پاسخ) | مشکل شبکه سرور است، نه رمز؛ از لینک خصوصی استفاده کنید |
| DNS | نام سرور ایمیل پیدا نشد | نام SMTP را بررسی کنید |
| TLS | اتصال امن برقرار نشد | پورت ۴۶۵ = TLS مستقیم، ۵۸۷ = STARTTLS |
| احراز هویت | App Password یا نشانی فرستنده پذیرفته نشد | App Password تازه در حساب Google بسازید |
| گیرنده رد شد | نشانی همکار پذیرفته نشد | نشانی ایمیل را بررسی کنید |

«پذیرفته شد» یعنی سرور ایمیل پیام را تحویل گرفت؛ رسیدن به صندوق را فقط خود گیرنده می‌تواند تأیید کند.

### تنظیم خصوصی فرستنده روی سرور

مالک خودش، روی رایانه خودش، این دستور را اجرا می‌کند. App Password در محل پنهان تایپ می‌شود و در Git، گزارش، خط فرمان یا خروجی دیده نمی‌شود:

```
ssh -i ~/.ssh/manage_preview_ed25519 manage@85.198.52.255
bash /opt/manage/deploy/preview/configure-smtp.sh
```

اسکریپت ابتدا از داخل image همان API اتصال، TLS و احراز هویت را بررسی می‌کند (بدون ارسال). فقط اگر نتیجه «موفق» باشد، پشتیبان `.env` را در `~/backups` می‌سازد، تنظیمات SMTP را اضافه و فقط سرویس API را دوباره راه‌اندازی می‌کند. پایگاه داده، Caddy، محافظ سایت، `AUTH_TOKEN_SECRET` و سایر تنظیمات دست نمی‌خورند. `--check` فقط بررسی می‌کند و `--disable` تنظیمات SMTP را برمی‌دارد.

### وضعیت فعلی Preview (۱۴۰۵/۰۸/۱۱)

سرور Preview در دیتاسنتر آروان (قیصر) به اینترنت بین‌الملل دسترسی ندارد: Gmail روی ۴۶۵/۵۸۷ (از میزبان و از داخل image API: `ETIMEDOUT` پیش از TLS)، Google، Microsoft، Yahoo، API سرویس‌های ایمیل (Brevo، SendGrid، Mailgun، Resend، Postmark) و Cloudflare همه بدون پاسخ‌اند؛ مقصدهای داخلی پاسخ می‌دهند. این محدودیت شبکه است و با تغییر کد یا رمز رفع نمی‌شود. تا رفع آن، «ساخت لینک دعوت خصوصی» را بزنید و لینک را فقط برای همان همکار بفرستید.
