# ورود شخصی Manage با Google Authenticator

این تغییر فقط برای Preview مستقل Manage است. حساب مالک با شناسه ایمیل تأییدشده خودش دعوت می‌شود؛ تغییرات این اپ به Source یا Production مربوط نیست. تنظیم فرستندهٔ Gmail و ساخت رمز برنامه را خود مالک در حساب خودش انجام می‌دهد.

## استفاده

1. در بخش «کارکنان»، مالک نام، ایمیل و نقش را وارد می‌کند تا دعوت خصوصی ۲۴ ساعته ایمیل شود؛ وضعیت استقرار و تنظیم فرستنده در [راهنمای کارکنان](STAFF_FA.md) است. مسیر قدیمی ساخت لینک خصوصی برای bootstrap حفظ شده است.
2. فرد لینک را باز می‌کند، رمز مخصوص Manage با حداقل ۱۲ نویسه انتخاب می‌کند و QR را در Google Authenticator اسکن می‌کند. برای Manage ورودی تازه بسازید؛ کد Source مستقل است.
3. اولین کد شش‌رقمی، حساب را فعال می‌کند. برای ورود بعدی صبر کنید کد تازه نمایش داده شود، سپس ایمیل، رمز و کد را وارد کنید.
4. صفحه «کاربران و دعوت‌ها» برای نقش دارای `user.manage` در دسترس است. لینک تازه برای دعوت ناتمام، لینک و اتصال ناتمام قبلی را باطل می‌کند.

QR و کلید دستی محرمانه‌اند. آنها را در چت، گزارش یا تصویر ارسالی منتشر نکنید. با بستن صفحه اتصال ناتمام، مدیر باید لینک تازه بسازد. بازیابی خودکار رمز، کد پشتیبان و بازیابی خودکار Authenticator هنوز ساخته نشده‌اند؛ بازیابی حساب فعال نیازمند اقدام کنترل‌شده مدیر و احراز هویت مالک است.

## تنظیم Preview

- متغیرهای API و gate باید هماهنگ باشند: `TOTP_AUTH_ENABLED=true`، `PUBLIC_APP_URL` برابر نشانی HTTPS Preview، و `AUTH_TOKEN_SECRET` تصادفی با حداقل ۳۲ نویسه در `.env` با دسترسی ۶۰۰.
- کلید را یک بار بسازید و همراه نسخه پشتیبان پایگاه داده، در محل امن نگه دارید. تغییر/گم‌شدن آن، کلیدهای Authenticator ذخیره‌شده را غیرقابل خواندن می‌کند.
- هر سه فایل Compose موجود را استفاده کنید: فایل اصلی، overlay Preview و overlay form-gate. فقط API دارای نشست تأییدشده با TOTP اجازه دسترسی به داده‌ها می‌دهد. رمز مشترک و نشست‌های قدیمی در حالت شخصی معتبر نیستند.
- قبل از migration 0005 از DB و `.env` نسخه پشتیبان خصوصی بگیرید. migration افزایشی است؛ down فقط برای DB دورریختنی و با تأیید حذف اطلاعات ورود مناسب است.
- برای اولین مالک، اسکریپت `node dist/scripts/invite-owner.js <email>` را در container API با پوشه خصوصی قابل‌نوشتن روی `/private` اجرا کنید. لینک فقط در `/private/owner-invite.txt` با دسترسی ۶۰۰ نوشته می‌شود. bootstrap فقط برای tenant ساختگی Preview/development مجاز است و حساب فعال موجود را بازنویسی نمی‌کند.

## کنترل‌های پیاده‌شده

رمز scrypt، کلید TOTP رمزگذاری‌شده با AES-256-GCM، دعوت و challenge با اثبات تصادفی و HMAC، انقضای دعوت ۲۴ ساعت / challenge ورود ۵ دقیقه / اتصال ۱۰ دقیقه، محدودیت تلاش و قفل حساب، رد بازپخش کد، مصرف تراکنشی challenge با قفل ردیف، نشست Secure/HttpOnly، کنترل نقش و جداسازی نمایندگی، audit بدون کلید و رمز. پاسخ‌های احراز هویت cache نمی‌شوند و پاسخ خصوصی دعوت/QR در جدول idempotency ذخیره نمی‌شود. پاک‌سازی demo در صورت وجود حساب شخصی متوقف می‌شود. زمان سرور باید با NTP همگام بماند.

## وضعیت تحویل

ورود شخصی در 2026-11-01 با SHA `58ad08c` روی Preview مستقل مستقر شد و هر پنج بررسی CI سبز است. دعوت خصوصی مالک ساخته شد؛ مالک در ادامه تأیید کرد خودش رمز را تعیین و Authenticator را متصل کرده و وارد شده است. این نتیجه تأیید مالک است؛ عامل رمز یا QR او را ندیده است. جزئیات در PROGRESS و TEST_REPORT ثبت شده‌اند.
